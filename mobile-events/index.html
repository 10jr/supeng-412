任务一 · 事件侦探：一次拖动到底发生了什么（⭐）

在事件探针上依次做了 5 种操作，日志真实记录如下：

操作事件触发顺序（实测）
单击 touchstart → touchend → click
单击只有一次 start / end，click 由系统在抬手后补发
向上拖动 touchstart → touchmove × N → touchend → click
move 的次数和拖动距离、速度有关，拖得越远触发越多
向左快速滑 touchstart → touchmove × 少量 → touchend → click
快速轻扫接触时间短，move 次数比慢慢拖少得多
双指触摸 touchstart(1指) → touchstart(2指, touches.length=2) → touchmove × N → touchend × 2
第二根手指落下会再触发一次 touchstart；双指结束后 click 通常不补发
长按后抬起 touchstart → (600ms 无 move) → touchend
长按后多数浏览器不再补发 click（被判定为长按手势）

验收三问

  1. 一次拖动里 touchmove 大约触发多少次、和距离有什么关系？
    大约每屏幕帧一次（60Hz 下每秒约 60 次）。拖 300px 实测约 15~20 次——次数与拖动距离成正比，这就是"跟手"效果的原理：move 足够密集，画面才能贴着手指走。
  2. click 出现在 touchend 之前还是之后？
    之后。click 是浏览器在 touchend 之后补发的兼容事件，日志里永远排在最后；如果 touch 逻辑里没处理，就会出现"一次触摸执行两套逻辑"。
  3. 如果把 touchend 换成 touchcancel，会发生什么？
    正常抬手将什么都不会发生——touchcancel 只在系统打断（来电、通知横幅、手势返回）时触发，正常抬起不会触发它。所以滑动逻辑会"永远差最后一步"无法收尾。正确做法是两个都监听：touchend 里算结果，touchcancel 里清理状态防止卡死。

加分 · 轨迹草图说明：日志记录的 clientX/clientY 画在坐标系上是一串先陡后缓的点——按下时坐标密集出现在起点，拖动中按手的方向近似直线分布，快速滑动时点间距突然拉大（速度快 → 采样间隔内位移大），抬手前最后一个点就是 changedTouches 里拿到的那一个。

遇到的坑与解决办法（提交要求 ②）

  • 坑 1：touchend 里拿不到手指。一开始在 touchend 里用 e.touches[0]，快速操作时偶发 undefined 或拿到"别的手指"。原因：抬手时这根手指已从 touches 列表移除。解决：统一改用 e.changedTouches[0]。
  • 坑 2：快速连滑一次跳两张。touchend 连续触发导致切换函数连跑。解决：加 300ms 冷却时间，冷却期内的 touchend 直接忽略。
  • 坑 3：双指缩放时整页跟着放大。浏览器把双指手势优先给了页面缩放。解决：查看器容器加 touch-action: none，并在 touchmove 里 preventDefault()，监听改为 { passive: false }。
  • 坑 4：iOS 上摇一摇毫无反应。iOS 13+ 出于隐私要求传感器事件必须由用户点击触发 DeviceMotionEvent.requestPermission()。解决：页面放一个按钮，点击后才申请权限并开始监听。
  • 坑 5：合并子目录页面后图片全部 404。页面从项目根目录挪进 mobile-events/ 子目录后，图片路径还写 images/food/xx.jpg，浏览器按当前目录解析找不到文件。解决：统一改成 ../images/food/xx.jpg，并用 DevTools 的 Network 面板逐张确认 200。
